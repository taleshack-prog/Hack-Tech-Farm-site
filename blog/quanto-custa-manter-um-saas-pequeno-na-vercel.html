Quanto Custa Manter um SaaS Pequeno na Vercel

2026-08-21 · 7 min de leitura · atualizado em 2026-08-24

O que compõe o custo de um SaaS na Vercel

O custo de hospedar um SaaS pequeno na Vercel não é um número único — é a soma de um plano base fixo mais uma camada variável que cresce com o uso. Essa distinção importa porque muita gente orçamenta só o primeiro item e é surpreendida pelo segundo.

A Vercel opera com três camadas de plano (Hobby, Pro e Enterprise) e, a partir do Pro, adiciona cobrança por consumo acima de cotas incluídas: banda de rede (bandwidth), execuções de Serverless Functions, minutos de build e uso da Edge Network.

Essas três entidades — Serverless Functions, Bandwidth e Edge Network — se relacionam diretamente: toda requisição que chega ao seu SaaS passa pela Edge Network da Vercel, que roteia para uma Serverless Function (ou Edge Function) quando há lógica de backend, e cada resposta enviada de volta ao cliente consome Bandwidth. Quanto mais chamadas de API o seu app fizer por usuário ativo, mais essas três linhas de custo sobem juntas.

O ponto prático para um fundador técnico é relacionar esse custo variável ao MRR do produto. Se a infraestrutura consome uma fatia crescente da receita recorrente mensal conforme a base de usuários cresce, o modelo de billing por uso deixou de ser vantagem e virou risco. Isso é diferente de um custo fixo previsível, que você consegue provisionar no orçamento sem sustos.

Planos da Vercel e para quem cada um serve

O plano Hobby é gratuito, mas os termos de uso da Vercel deixam explícito que ele é destinado a projetos pessoais e não-comerciais. Rodar um SaaS com clientes pagantes no Hobby viola os termos de serviço, independentemente de tecnicamente funcionar.

O plano Pro é o ponto de entrada real para produtos comerciais. Ele cobra uma mensalidade fixa por membro do time, mais consumo acima das cotas incluídas de banda, execuções de função e build minutes — os valores exatos e as cotas incluídas mudam com frequência, então o pricing oficial da Vercel é a única fonte confiável no momento em que você for orçamentar.

O plano Enterprise entra em cena quando o SaaS precisa de SLA contratual, suporte dedicado, controles de compliance mais rígidos ou volume de tráfego que já ultrapassa qualquer estimativa de self-service. Para um SaaS em estágio inicial, raramente faz sentido — o custo de negociação e o compromisso mínimo geralmente superam o problema que ele resolve.

Plano Uso comercial permitido Modelo de billing Indicado para
Hobby Não Gratuito, com limites Projetos pessoais, protótipos
Pro Sim Fixo por membro + uso variável SaaS em estágio inicial a médio
Enterprise Sim Negociado, com SLA Alto tráfego, requisitos de compliance

Onde o custo surpreende: funções serverless e edge

A maior parte das faturas inesperadas na Vercel não vem do plano em si, vem do comportamento das funções.

Cold starts — o tempo que uma função leva para "acordar" quando não foi invocada recentemente — não são cobrados como uma linha separada, mas afetam a duração de execução medida, e duração de execução é exatamente o que compõe parte do custo de Serverless Functions. Uma função mal otimizada, com dependências pesadas carregadas a cada invocação, paga esse preço de forma silenciosa.

Edge Functions e Serverless Functions têm modelos de billing diferentes na Vercel — a documentação de runtimes da Vercel detalha o comportamento de cada uma. Migrar lógica para Edge sem entender essa diferença pode tanto economizar quanto piorar a fatura, dependendo do padrão de uso.

Outra linha de custo frequentemente esquecida é a otimização automática de imagens. Ela é conveniente — reduz payload para o usuário final — mas cada transformação de imagem consome cota própria, separada da banda geral do projeto, segundo a documentação de Image Optimization. Um SaaS com muitos uploads de usuário (avatares, thumbnails, galerias) pode ver essa linha crescer mais rápido que o tráfego de página.

Um endpoint de API que faz fetch redundante, não usa cache e responde payloads maiores que o necessário infla três métricas ao mesmo tempo: duração de função, banda e, indiretamente, o número de invocações se o cliente reage a timeouts com retry automático.

// Exemplo de handler que reduz payload e evita trabalho redundante
export const config = { runtime: 'edge' };

export default async function handler(req) {
 

  const data = await getMinimalUserPayload(req);
  const response = new Response(JSON.stringify(data), {
    headers: { 'Cache-Control': 's-maxage=60' },
  });

  return response;
}

Tabela comparativa: Vercel vs alternativas de deploy

Nenhuma plataforma é objetivamente melhor em todos os critérios — a escolha depende do estágio do SaaS e da tolerância a esforço operacional.

Critério Vercel Pro VPS próprio Railway / Render
Previsibilidade de custo Baixa a média (uso variável) Alta (custo fixo) Média
Esforço de manutenção Baixo Alto Baixo a médio
Escalabilidade automática Nativa Manual Parcial
Velocidade de deploy Alta Baixa Alta
Controle de infraestrutura Baixo Total Médio

Sair da Vercel compensa financeiramente quando o tráfego é grande o suficiente para que o custo de uso variável ultrapasse, com folga, o custo fixo de operar um VPS mais o tempo de engenharia necessário para mantê-lo. Abaixo desse ponto de equilíbrio, a velocidade de deploy da Vercel geralmente vale o prêmio pago.

Como estimar seu custo mensal antes de lançar

Uma estimativa grosseira, mas útil, parte de três variáveis: usuários ativos, chamadas de API por usuário e tamanho médio de payload por chamada. Multiplicando essas três variáveis você chega a um volume de dados e de invocações que pode ser confrontado com as cotas incluídas do plano Pro.

A Vercel disponibiliza uma calculadora de preços no próprio site de pricing, que permite simular cenários de tráfego antes de comprometer orçamento. Rodar essa simulação antes do lançamento é mais barato do que descobrir o número na fatura seguinte.

É prudente adicionar uma margem de segurança de tráfego para eventos pontuais de pico — um lançamento em canais como Product Hunt pode multiplicar o volume normal de requisições por um fator alto e imprevisível em poucas horas.

Há também uma relação pouco discutida entre churn e desperdício de infraestrutura: usuários que assinam, geram tráfego intenso nos primeiros dias e cancelam antes de gerar MRR suficiente para cobrir o custo variável que consumiram representam prejuízo direto de infraestrutura, não só perda de receita futura. Monitorar esse padrão é parte do controle de custo, não só de retenção.

Esse artigo é muito útil para quem está começando a desenvolver seus próprios produtos. Previsibilidade e escalabilidade do produto devem ser levaods em conta, para não haver surpresas posteriores.

Quando migrar de arquitetura faz sentido

O sinal mais claro de que chegou a hora de migrar é quando o custo de infraestrutura, como percentual do MRR, para de cair ou começa a subir mesmo com otimizações de código já aplicadas. Isso indica que o modelo de billing por uso deixou de acompanhar a economia do negócio.

O trade-off central é entre velocidade de deploy e controle de custo. A Vercel otimiza para a primeira; uma arquitetura própria com VPS ou Kubernetes otimiza para a segunda, ao custo de mais engenharia de infraestrutura contínua.

Essa decisão não deveria ser tomada isoladamente — ela é parte de uma discussão maior sobre arquitetura de SaaS, que cobrimos com mais profundidade no Guia Definitivo de Arquitetura SaaS em 2026.

Se sua equipe está tentando decidir entre continuar na Vercel ou migrar para uma arquitetura própria, vale conversar com quem já desenhou essa transição para outros produtos — fale com o time da Hack Tech Farm através da página de contato.

Perguntas Frequentes

Vercel é grátis para SaaS pequeno?

Não para uso comercial. O plano Hobby é gratuito, mas seus termos de serviço proíbem projetos comerciais — um SaaS com clientes pagantes precisa do plano Pro ou superior.

Quanto custa o plano Pro da Vercel por mês?

O valor exato e as cotas incluídas mudam com frequência. Consulte sempre o pricing oficial da Vercel antes de orçamentar, em vez de confiar em números desatualizados de terceiros.

O que mais consome banda na Vercel além do frontend?

Chamadas de API via Serverless Functions, otimização automática de imagens e assets estáticos servidos pela Edge Network somam-se ao consumo de banda, muitas vezes superando o tráfego de páginas HTML puras.

Dá para prever a fatura da Vercel antes de escalar?

Sim, de forma aproximada. A calculadora de preços oficial permite simular usuários ativos, chamadas de API e payload médio antes do lançamento, reduzindo o risco de surpresas na fatura.

Quando vale a pena sair da Vercel para um VPS?

Quando o custo variável de uso, somado ao longo dos meses, supera com folga o custo fixo de manter um VPS mais o tempo de engenharia necessário para operá-lo com segurança e escala equivalente.
